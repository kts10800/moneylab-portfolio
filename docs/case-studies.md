# 문제 해결 사례

## 1. 파일을 복사하지 않는데도 가져오기가 느렸습니다

**문제:** 개발 중 기록에서 55.25초 동안 기존 파일 5,413개를 확인했고 실제 복사는 0개였습니다. 전송량만 보면 멈춘 것처럼 보이지만, 작은 원격 파일을 하나씩 확인하는 작업이 진행 중이었습니다.

**본인 기여:** 반복해서 모든 파일을 확인하는 사용 경험의 문제를 제기하고, 이미 있는 자료는 대조 후 유지하며 없는 자료만 가져오도록 요구했습니다.

**구현:** 디렉터리 목록의 크기·수정 시각과 이전 검증 기록을 활용하고, 신규·변경 파일만 필요한 검사를 수행하도록 개선했습니다. 파일 검증 결과는 묶어서 저장합니다. 크기·수정 시각이 같다는 사실만으로 내용 무결성을 완전히 보장하지는 않으므로 분석 경로의 해시 확인을 유지합니다.

**확인:** 로컬 시험 600개에서 최초 처리 1.015초, 반복 확인 0.094초, 반복 복사 0개·전송 0바이트·오류 0개가 기록됐습니다. 실제 공유 폴더의 전체 전송 속도를 보장하는 수치는 아닙니다.

## 2. GPU를 쓰면 항상 빨라지는지 확인했습니다

**문제:** 많은 전략을 비교하는 계산과 단일 설정의 순차 주문 계산은 구조가 달랐습니다.

**본인 기여:** 대량 계산의 GPU 사용과 실행 진행 표시를 요구했고, 속도 개선은 측정과 결과 일치로 판단하도록 개발 기준을 정했습니다.

**구현·판단:** 병렬화 가능한 신호·봇 계산은 GPU에서 묶어서 처리하고 CPU 결과와 비교합니다. 작은 리플레이 시험에서는 GPU 혼합 방식이 더 느렸기 때문에 CPU를 기본으로 선택했습니다.

**확인:** GPU 모의운용 계산에서 약 11배 향상을 기록한 사례와, 초기화·전송을 포함하면 GPU가 느린 사례를 함께 공개합니다. 측정 범위가 다르므로 두 결과를 하나의 성능 주장으로 합치지 않습니다.

## 3. 많은 데이터가 좋은 연구 자료를 뜻하지 않았습니다

**문제:** 저장 건수만으로는 특정 종목이 언제, 얼마나 연속해서 관측됐는지 알기 어려웠습니다.

**본인 기여:** 날짜·종목별 수집 타임라인, 막대 선택 후 가격 그래프, 정렬과 쉬운 설정 설명을 요청하고 실제 화면을 보며 개선점을 제시했습니다.

**구현:** 한국시간 기준 조회, 관측 공백별 구간 분리, 데이터 종류별 출처 표시, 날짜 색인과 결과 캐시를 도입했습니다.

**남은 과제:** 구독 중 자료가 없었다는 사실만으로 거래가 없었다고 단정할 수 없습니다. 공급자 누락과 연결 장애 등 근거가 부족한 경우는 미확인으로 표시해야 합니다. 긴 관찰 정책의 효과도 실제 장중 자료로 측정해야 합니다.
